## ❓ Нужно от команды

- **Датасет NASK** («Przykładowe reklamy typu scam», канал NASK в Discord) → положить в `data/nask/` как есть (в git не попадёт — NASK запрещает публиковать их материалы). Дальше три команды: `./start.sh ingest data/nask --show` (как распознались колонки и картинки) → `./start.sh run data/nask` → `./start.sh eval` (если есть метки кампаний). Пришлите вывод `ingest` — если колонки не распознались, добавим синонимы за минуты.
- **LLM для прогона NASK — решить:** локальная Ollama (qwen3.5:9b) работает, но ~13 с на материал (73 материала ≈ 16 мин; без LLM — 10 с). Поэтому `demo` и панель по умолчанию идут **без LLM** (эвристики), а `run` использует LLM из `.env`. Варианты: (а) без LLM (`--no-llm`), (б) ключ OVHcloud в `.env` — быстрее, (в) LLM только для анализа одного нового материала в панели.
- (по желанию) 3–5 фото самых частых «лиц» скам-рекламы → `reference/faces/<Imię_Nazwisko>/*.jpg` — база для распознавания лиц (NASK прямо это предлагает). Без неё лица всё равно сравниваются между материалами, но без имени.

## Известные ограничения (честно для жюри)

- Только URL без сети: неизвестный сокращатель ссылок, общий для двух кампаний, выглядит как общий домен → лишние связи. С сетью цепочка редиректов это решает; известные сокращатели (bit.ly и др.) уже в списке.
- Тексты одной кампании, написанные разными шаблонами, без общего следа (телефон, домен, картинка) не склеиваются — кампания может распасться на части. Это сознательный выбор в пользу точности.
- Веса откалиброваны на синтетике — нужна проверка на данных NASK.
- Docker: первая сборка с нуля ~25 мин на медленной сети (образ 1.8 ГБ) — собрать заранее. `start.bat` не проверен на настоящем Windows.
